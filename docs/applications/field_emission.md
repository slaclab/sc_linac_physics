# README

The purpose of the GUI is to aid in the visualization and characterization of field emission from linac cavities. This collection of scripts is to generate the appropriate data files, update, and run the field emission GUI.

Radiation data is collected by one of two decarads with 10 channels each and is recorded in the archiver. The display works to end dependency on slow archiver retrieval as well as consolidating data to one base.

The collection consists of:

## GUI Suite

- **`field_emission_runs.csv`**: the list of measurement runs, one row per run, in the "To Add Data" column order below. This is the only data kept in git.

- **`field_emission_data.hdf5`**: a cache of archiver data for every run in the run list, in `/home/physics/srf/field_emission/` on Linux (`~/.sc_linac_physics/field_emission/` elsewhere). Each dataset's first column is cavity amplitude, then decarad channels 1–10. Built from the run list; safe to delete, the next sync rebuilds it.

- **`field_emission_gui.py`**: read-only version of the display, intended for public use. Launched by `sc-linac field-emission`. On open it syncs the cache (see Building the Cache) with the selection panel disabled.


- **`field_emission_gui_update.py`**: display with addition of "Add New Data" button. Included to ease process of updating core `.h5` file with the availability of new field emission data.


- **`measurements.py`**: called by `field_emission_gui.py` for data matching with .hdf5 file.


- **`plot_me.py`**: called by `field_emission_gui.py` for plotting. Contains the `fit_equation` method, to be further adjusted for improved fit line.


## Additional Scripts

- **`amp_vs_radiation_from_csv.py`**: takes start and end time data to find radiation during active cavity session. Necessary for gui_updater use. Contains the `align_pvs_to_common_time` method, used to give common timebase between process variables which may have inconsistencies in time data.


- **`gui_updater.py`**: worker to update gui. Validator for single entry data and csv reader for multiple data entry.


- **`update_h5py.py`**: converts CSV files with amplitude vs radiation data (generated by `amp_vs_radiation.py`) to hdf5 additions in the main `field_emission_data.hdf5` file.


## Building the Cache

The display syncs the cache on open: any run in the run list that is missing or only partly written is fetched from the archiver. Each run takes a few minutes (155 s for a 47-minute window), so building all 80 runs from empty takes hours. Build it once without the display:

```bash
python -m sc_linac_physics.applications.field_emission.gui_updater
```

Each run is written as soon as it is fetched, so an interrupted build keeps the runs it finished. Rerun the same command to continue.

## To Add Data

Currently, addition of cryomodule data can be achieved with the "Add New Data" button at the top right of the field_emission_gui_update.py display. Data can be added individually, by cryomodule, or by CSV for multiple entries.  If using CSV, though actual header names can be anything, columns should be written in the following order:

"Cryomodule, Start Date, Start Time, End Date, End Time, Decarad #, Link to Measurement, Notes, Recharacterization, Multipacting, Commissioning"

After successful update, select any other cryomodule in the display. Click back to the cryomodule of interest and the new data should be reflected in the GUI.

> **NOTE:** CSV reader is written with the expectation of a header row in multi-entry CSV.

> **NOTE:** Including "#" in the first column of a row will exclude it from h5 conversion.

> **NOTE:** A column should be included for end date in the case of overnight operation where the start date and end date will not be the same (albeit only one day apart), regardless of if that column has data.
