# Q0 Measurement

`applications/q0/` measures the intrinsic quality factor (Q0) of individual SRF cavities. Q0 quantifies how efficiently a cavity stores RF energy — higher Q0 means less cryogenic heat load for the same accelerating gradient.

## Measurement principle

For the full operator walkthrough, see [the Q0 explainer](../explainers/q0.md).

Q0 comes from the downstream liquid helium level (`ds_level_pv`): how fast it drops (dLL/dt) with RF on, compared against how fast it drops for known heater loads. Each dLL/dt is a `siegelslopes` fit of level vs. time (`DataRun.dll_dt`, `q0_utils.py`).

1. **Calibration** (`Q0Cryomodule.take_new_calibration`). `fill()` turns every cavity off, sets the JT valve to auto and the heater to 0, then waits for the level. The JT valve is held at the reference position (`valveParams.refValvePos`). The heater then steps through `linspace(heat_start, heat_end, num_cal_steps)`. The GUI defaults are 130 W to 160 W in 5 points (`Q0MeasurementWidget` spinboxes). Called directly, the defaults are 130 W to 160 W in `NUM_CAL_STEPS` = 7 points. Each step records level until it falls `ll_drop` %. `Calibration.dLLdt_dheat` is a `linregress` of dLL/dt against average heater readback minus the reference heat load.
2. **RF measurement** (`Q0Cryomodule.takeNewQ0Measurement`). The cavities stay on at their requested amplitudes and the heater is at the reference load. The code records the level drop, refills with the cavities off, then runs one heater step at reference + `FULL_MODULE_CALIBRATION_LOAD` (80 W). The RF heat load is the calibration's heat for the RF dLL/dt, plus an offset. That offset is the 80 W run's measured heater readback minus the heat the calibration predicts for it (`Q0Measurement.adjustment`). The 80 W run accounts for drift since the calibration was taken.

`q0_utils.calc_q0` then returns the uncorrected value:

```
Q0 = (A_eff × 1e6)² / (R/Q × P_RF)
A_eff = sqrt(sum of squared cavity amplitudes, MV)
```

`R/Q` is 1012 Ω, or 750 Ω on harmonic linearizer cryomodules (`Q0Cavity.r_over_q`). `calc_q0` also computes a helium-temperature-corrected Q0, but it only returns that when `use_correction=True`. `Q0Measurement.q0` does not set it.

## Main classes

### `Q0Cryomodule` (`q0_cryomodule.py`)

Extends `Cryomodule`. Manages:
- Loading and saving calibration and measurement JSON files (paths under [Data files](#data-files))
- JT valve reference position and heater setpoint state
- Coordinating multi-cavity RF runs

### `Q0Cavity` (`q0_cavity.py`)

Extends `Cavity` with:
- `r_over_q`: geometry constant (1012 or 750 depending on HL/normal)
- `ready_for_q0`: flag indicating cavity can participate in RF measurement

### `Calibration` (`calibration.py`)

Holds one or more `HeaterRun` objects, each representing a single heat-load step. After all heater runs complete, linear regression on `(heat_load, ΔLL/Δt)` pairs produces the calibration slope used to subtract background in the RF measurement.

### `Q0Measurement` (`rf_measurement.py`)

Records one RF measurement run: which cavities participated, their amplitudes, and the measured ΔLL/Δt. Computes Q0 using the calibration slope.

## Workflow

```
Q0GUI
├── Select cryomodule + cavities
├── Reference cryo params (JT position, heater load) from spinboxes → valveParams
├── Calibration
│   ├── [Load existing calibration from JSON] or
│   └── [Run new calibration]
│       └── CalibrationWorker → take_new_calibration
│           → Heater steps, default 130–160 W in 5 points
│           → Each step: record LL until it drops ll_drop %
│           → Save to JSON
└── RF Measurement
    ├── [Load existing RF run] or
    └── [Run new measurement]
        └── Q0Worker → takeNewQ0Measurement
            → Wait for each cavity's AACT to reach its amplitude
            → Record LL until it drops ll_drop %
            → Cavities off, heater run at reference + 80 W
            → Compute Q0, display results + pyqtgraph plots
```

Both the calibration and RF measurement run in background `Worker` threads. The GUI remains responsive during the multi-minute data collection windows.

## Data files

`Q0Cryomodule.__init__` puts every file inside the installed package directory (`applications/q0/`), one file per cryomodule, keyed by timestamp:

| What | Index (results) | Raw data |
|---|---|---|
| Calibrations | `calibrations/cm{name}.json` | `data/calibrations/cm{name}.json` |
| Q0 measurements | `q0_measurements/cm{name}.json` | `data/q0_measurements/cm{name}.json` |

New runs are written to these same files. All four folders, subfolders included, ship in the built wheel.
