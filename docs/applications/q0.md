# Q0 Measurement

`applications/q0/` measures cavity Q0 from the cryomodule's liquid helium level. For how a calibration and an RF measurement run, how Q0 is computed, and the caveats, see [the Q0 explainer](../explainers/q0.md).

## Entry point

```bash
sc-q0
```

## Data files

`Q0Cryomodule.__init__` puts every file inside the installed package directory (`applications/q0/`). There is one file per cryomodule, keyed by run start time:

| What | Index (results) | Raw data |
|---|---|---|
| Calibrations | `calibrations/cm{name}.json` | `data/calibrations/cm{name}.json` |
| Q0 measurements | `q0_measurements/cm{name}.json` | `data/q0_measurements/cm{name}.json` |

The GUI lists past runs from the index files and loads raw data from the `data/` files. `data/edited_calibrations/cm01.json` is not read by the code.

## Adding data

Each new calibration or Q0 measurement adds one entry to both files for its cryomodule (`q0_utils.update_json_data`). A missing file is created empty on first use. New JSON files ship in the built wheel through `recursive-include src *.json` in `MANIFEST.in`. The `pyproject.toml` package-data globs do not reach the JSON files in subfolders or in `q0_measurements/`.

## Files

| File | What it holds |
|---|---|
| `q0_gui.py` | `Q0GUI`, the main window |
| `q0_measurement_widget.py` | `Q0MeasurementWidget`, the spinboxes and buttons |
| `q0_gui_utils.py` | Workers for setup, calibration and RF runs, plus past-run selection widgets |
| `q0_cryomodule.py` | `Q0Cryomodule`: JT valve and heater PVs, calibration and RF run sequences, file paths |
| `q0_cavity.py` | `Q0Cavity`, with `r_over_q` |
| `calibration.py` | `Calibration`: heater runs, fit, save and load |
| `rf_measurement.py` | `Q0Measurement`: RF and heater runs, heat load, Q0, save and load |
| `rf_run.py` | `RFRun`: one RF data run |
| `q0_utils.py` | Constants, `DataRun`/`HeaterRun`, `calc_q0`, JSON helpers |
