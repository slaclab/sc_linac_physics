# How the Q0 app works

The Q0 app (`sc-q0`) measures how much heat the RF in a cryomodule's cavities
puts into the helium. From that it works out Q0 for the cavities you ran. This
page goes through what the app does to the machine at each step, what to expect
while it runs, and how it turns liquid level readings into a Q0. Sections 1–5
are for anyone running the app. Sections 6–8 cover the arithmetic and the fit
choices.

## 1. The idea in one paragraph

Heat in the cryomodule boils off liquid helium, so the downstream liquid level
(LL) falls. The app holds the helium supply valve (the JT valve) at a fixed
position, so nothing refills the helium while it watches the level fall.

- **Calibration.** With the RF off, the app sets the electric heaters to several
  known powers. For each one it records how fast LL falls. That gives a line:
  LL fall rate against watts.
- **RF measurement.** The app runs the cavities at the amplitudes you chose and
  records how fast LL falls. It reads the heat off the calibration line. Q0
  follows from that heat and the cavity amplitudes.

The method, how it was developed, and its first results across the linac are in
<span class="cite">Zacarias et al., SRF2023, [MOPMB090](https://proceedings.jacow.org/srf2023/papers/mopmb090.pdf)</span>. Later sections point to it where the code
follows a choice the paper explains.

### Words used on this page

| Word | What it means in this app |
|---|---|
| **LL** | The downstream liquid level readback, in %. Measurements happen between 90 and 93 (`MIN_DS_LL`, `MAX_DS_LL`) <span class="cite">`q0_utils.py::MIN_DS_LL, q0_utils.py::MAX_DS_LL`</span>. |
| **dLL/dt** | How fast LL is falling: the slope of a straight line through the LL readings of one run. |
| **JT valve, AUTO / MANUAL** | In AUTO the app gives the valve a DS level setpoint to refill to. In MANUAL the app walks the valve to a fixed position and leaves it there <span class="cite">`q0_cryomodule.py::Q0Cryomodule.fill`</span>, <span class="cite">`q0_cryomodule.py::Q0Cryomodule.jt_position`</span>. |
| **Heaters, MANUAL / SEQUENCER** | The app puts the heaters in MANUAL to set a power, and hands them back to SEQUENCER when it is done <span class="cite">`q0_cryomodule.py::Q0Cryomodule.heater_power`</span>, <span class="cite">`q0_cryomodule.py::Q0Cryomodule.restore_cryo`</span>. |
| **Reference parameters** | A JT valve position and a heater power ("Electric Heat Load Offset") where the level holds steady. Every run starts from them. The paper's baseline is 48 W on the heaters with RF off, which is also the code's default (`MINIMUM_HEATLOAD`) <span class="cite">`q0_utils.py::MINIMUM_HEATLOAD`</span>. |
| **A run** | One stretch of LL readings at fixed conditions, from the starting level until LL has fallen by the chosen drop. |

## 2. Before you start

1. Launch `sc-q0` and pick a cryomodule. Nothing talks to the machine until
   you do.
2. Check **Cryo Permission**. Every button that starts a calibration, an RF
   measurement or a parameter setup first checks
   `CRYO:<CM>:0:CAS_ACCESS`. If access is not granted it stops with *"Required
   cryo permissions not granted - call cryo ops"*
   <span class="cite">`q0_cryomodule.py::Q0Cryomodule.cryo_access_granted`</span>,
   <span class="cite">`q0_gui_utils.py::NO_CRYO_ACCESS`</span>.
3. Enter the **reference parameters**: JT valve position and Electric Heat Load
   Offset. Taking a calibration or an RF measurement uses whatever is in these
   two boxes. The heater value is used both as the setpoint and as the
   reference readback
   <span class="cite">`q0_gui.py::Q0GUI.takeNewCalibration “refHeatLoadAct=self.main_widget.ref_heat_spinbox.value()”`</span>.
4. If you don't have reference parameters, **Set Up for New Parameters** sets
   the heaters to the box value and walks the JT valve to the box position. It
   then puts the JT back in AUTO and reports *"Cryo setup for new reference
   parameters in ~1 hour"*
   <span class="cite">`q0_gui_utils.py::CryoParamSetupWorker.run`</span>.

    The app does not read the result back. Per the paper, the baseline is
    the JT position the control loop settles at after about an hour with RF
    off, once neither the JT position nor the DS level changes more than
    normal noise. Finding that position is still a manual step
    <span class="cite">Zacarias et al., SRF2023, [MOPMB090](https://proceedings.jacow.org/srf2023/papers/mopmb090.pdf)</span>. Enter it, and the heater value
    used, in the two boxes. The code that searched the archiver for a steady
    period is commented out (`getRefValveParams`).

The **Measurement Settings** box applies to both calibration and RF runs:

| Setting | Default | What the app does with it |
|---|---|---|
| Starting liquid level | 93 (90–93) | Refills to this level before each run |
| Desired liquid level drop | 3 (1–3) | Ends each run when LL has fallen this much |
| Number of LL points to average | 10 | How many recent readings are averaged when it decides "full" or "dropped enough". The stored readings are not averaged <span class="cite">`q0_cryomodule.py::Q0Cryomodule.averaged_liquid_level`</span>. |

## 3. Taking a calibration

**Take New Calibration** steps the heaters through *Number of data points*
evenly spaced powers from *Starting heater setpoint* to *End heater setpoint*.
The defaults are 5 points from 130 to 160 W: 130, 137.5, 145, 152.5 and 160 W
<span class="cite">`q0_cryomodule.py::Q0Cryomodule.take_new_calibration “for setpoint in linspace(heat_start, heat_end, num_cal_steps):”`</span>.

For each power, in order:

| Step | What the app writes | Waits for |
|---|---|---|
| Refill | DS level setpoint = starting level, JT → AUTO, heaters → 0 W, cavities off | Averaged LL to reach the starting level <span class="cite">`q0_cryomodule.py::Q0Cryomodule.fill`</span> |
| Lock | JT → MANUAL, walked to the reference position about 1% every 3 s. Then heaters → reference power. | JT readback within 2% of target (`VALVE_POS_TOL`) <span class="cite">`q0_cryomodule.py::Q0Cryomodule.setup_cryo_for_measurement`</span> |
| Record | Heaters → this step's power. LL and heater readback are recorded. | Averaged LL to fall by the chosen drop, checked every 10 s <span class="cite">`q0_cryomodule.py::Q0Cryomodule.launchHeaterRun`</span>, <span class="cite">`q0_cryomodule.py::Q0Cryomodule.wait_for_ll_drop`</span> |

After the last step the app saves the runs, sets the heaters back to the
reference power and restores cryo (section 5). It then saves the calibration
slope. The status line reads *"Calibration Loaded"*, and the RF Measurement
section unlocks.

Each step's heat is recorded as the average heater readback minus the
reference power
<span class="cite">`q0_cryomodule.py::Q0Cryomodule.launchHeaterRun “reference_heat=self.valveParams.refHeatLoadAct”`</span>,
<span class="cite">`q0_utils.py::DataRun.average_heat`</span>.
The code has no fixed duration. Each step lasts as long as the refill plus the
drop takes, and the console prints the total in hours at the end.

## 4. Taking an RF measurement

Check the cavities to include and set their amplitudes. Each box starts at
16.6 MV or the cavity's maximum, whichever is lower. Offline cavities are
unchecked
<span class="cite">`q0_gui_utils.py::CavAmpControl.connect “min(16.6, cavity.ades_max)”`</span>.
**Take New RF Measurement** then does the following:

| Stage | What the app does | Waits for |
|---|---|---|
| 1. Refill | Same refill as calibration, cavities off <span class="cite">`q0_cryomodule.py::Q0Cryomodule.setup_for_q0`</span> | Starting level |
| 2. Ramp | Each checked cavity, in parallel: RF off, SSA calibration, tune to resonance, characterize. Then 5 MV, SEL, piezo feedback on, SELA. Then it walks up to the target, 0.5 MV steps to 10 MV and 0.1 MV after that <span class="cite">`cavity.py::Cavity.setup_rf`</span> | Every cavity to finish <span class="cite">`q0_gui.py::Q0GUI.ramp_cavities`</span> |
| 3. Refill with RF on | Refill again, cavities left on. Heaters go to 0 W during the refill, then to the reference power after the JT lock <span class="cite">`q0_cryomodule.py::Q0Cryomodule.takeNewQ0Measurement “self.setup_cryo_for_measurement(desired_ll, turn_cavities_off=False)”`</span> | Starting level, then each cavity's AACT within 0.1 MV of its target |
| 4. RF run | Records LL, heater readback and DS pressure | LL to fall by the drop |
| 5. Heater run | Refill with cavities **off**. JT lock, then heaters → reference + 80 W (`FULL_MODULE_CALIBRATION_LOAD`). Records LL and heater readback. | LL to fall by the drop |
| 6. Finish | Saves the runs. Heaters → readback − 80 W. Computes Q0, saves the result and restores cryo. | — |

The heater run gives each measurement its own check against the calibration
line (section 6). The status line ends with *"Recorded Q0: …"*.

The RF section's *Calibration Heat Load* box shows 80 and is greyed out. The
80 W comes from `FULL_MODULE_CALIBRATION_LOAD`, not from the box
<span class="cite">`q0_utils.py::FULL_MODULE_CALIBRATION_LOAD`</span>.

## 5. Aborting and restoring

| Button | What happens |
|---|---|
| **Abort Calibration** / **Abort RF Measurement** | Sets a flag that the waiting loops check (every 10 s while waiting for the level). At the next check the app flags every cavity to abort, restores cryo and stops <span class="cite">`q0_cryomodule.py::Q0Cryomodule.check_abort`</span>. The JT walk only checks between whole steps. |
| **Restore Cryo to Standard Values** | JT → AUTO, DS level setpoint → 92, heaters → SEQUENCER, in that order. Each is tried even if an earlier one fails <span class="cite">`q0_cryomodule.py::Q0Cryomodule.restore_cryo`</span>. |
| *(automatic)* RF measurement error | Any error during stages 3–6 runs a full shut-off: heaters → SEQUENCER, JT → AUTO, every cavity and SSA off <span class="cite">`q0_gui.py::Q0GUI._shut_off_after_error`</span>, <span class="cite">`q0_cryomodule.py::Q0Cryomodule.shut_off`</span>. |

A calibration error, or an error during the RF refill or ramp (stages 1–2),
only shows the message. Unlike an abort, it restores nothing, so press
**Restore Cryo** yourself.

### Looking at past results

**Load Existing Calibration** and **Load Existing RF Measurement** list every
saved timestamp for the selected cryomodule. Picking one loads it, and
**Show Calibration Data** / **Show RF Data** plot the LL readings and the fit
line. A calibration has to be loaded before an RF measurement can be loaded or
taken. Results are saved inside the installed package's `applications/q0/`
folders, one JSON file per cryomodule.

## 6. From LL samples to Q0

Each run (a calibration step, a Q0 heater run, a Q0 RF run) records the raw DS
level monitor values against time
<span class="cite">`q0_cryomodule.py::Q0Cryomodule.monitor_ll “ll_data[datetime.now().timestamp()] = value”`</span>.
The averaging buffer next to it is not what gets stored.

| Step | What the code does | Where |
|---|---|---|
| 1. Run slope | dLL/dt for each run: `siegelslopes` over the run's samples. `linregress` is used if `USE_SIEGELSLOPES` is False. | <span class="cite">`q0_utils.py::DataRun.dll_dt`</span>, <span class="cite">`q0_utils.py::USE_SIEGELSLOPES`</span> |
| 2. Calibration line | `linregress` of each calibration run's dLL/dt against its average heater readback. The slope is `dLLdt_dheat` and the intercept is `adjustment`. | <span class="cite">`q0/calibration.py::Calibration.dLLdt_dheat`</span> |
| 3. Heat load | `raw_heat + adjustment`. Here `raw_heat` is the RF run read off the line. The second `adjustment` (the measurement's own) is the heater run's known heat minus where the line puts it. | <span class="cite">`rf_measurement.py::Q0Measurement.heat_load`</span>, <span class="cite">`rf_measurement.py::Q0Measurement.adjustment`</span> |
| 4. Q0 | `calc_q0` with the root-sum-square of the cavity amplitudes. It is called uncorrected, because `use_correction` defaults to False. | <span class="cite">`rf_measurement.py::Q0Measurement.q0`</span>, <span class="cite">`q0_utils.py::calc_q0 “return corrected_q0 if use_correction else uncorrected_q0”`</span> |

### Three ways to fit a line

Steps 1 and 2 each fit a straight line through a cloud of points. There is
more than one reasonable way to pick "the" line, and this page compares three.
All three are in `scipy.stats`.

| Fit | How it picks the line | Strength | Weakness |
|---|---|---|---|
| `linregress` (least squares) | The line that makes the sum of *squared* vertical misses as small as possible | Uses every point fully, so with ordinary noise it wobbles least | A few wild points pull it hard, because a miss counts as its square |
| `siegelslopes` (repeated medians) | For each point, takes the median of the slopes from it to every other point. The line's slope is the median of those. | A few wild points barely move it | With ordinary noise it wobbles a bit more than least squares |
| `theilslopes` | The median of the slopes over all pairs of points | Resists wild points, though fewer than `siegelslopes` | Wobbles a little more than least squares, less than `siegelslopes` |

A median is the middle value once the values are sorted, so it ignores how
extreme the outer values are. That is where the robust fits get their
resistance. On a clean straight line with ordinary noise all three give nearly
the same slope. They part ways when the data bends or has outliers.

The calibration intercept cancels in step 3. Algebraically the heat load is

```text
heat_load = heater average_heat + (rf dLL/dt − heater dLL/dt) / dLLdt_dheat
```

The measurement's own `adjustment` is the paper's drift correction. Without it,
the heat came out quite different depending on which calibration was used and
how old it was, so a heater-only run follows every RF run
<span class="cite">Zacarias et al., SRF2023, [MOPMB090](https://proceedings.jacow.org/srf2023/papers/mopmb090.pdf)</span> (Fig. 3).

The Q0 is the paper's *effective* Q (its Eq. 4): one number for the
cryomodule, chosen so that the cavities together dissipate the measured heat.
The code builds it from the root-sum-square of the amplitudes, so
`effective_amplitude² = Σ amplitude²`.

So the Q0 depends on the calibration *slope* and on the difference between the
two run slopes. Uncorrected Q0 is proportional to 1 / heat load, so a heat
load that reads 5% high gives a Q0 that reads about 5% low.

## 7. Which fit is better: what the packaged data says

Compared on 2026-10-15 over everything in `q0/data/`. The heater readback was
the reference.

**Calibration linearity.** Within a calibration, dLL/dt should line up with
heater power. The test asks how well each fit's slopes make that line, using
runs the line has not seen:

1. Hide one run, say the 145 W step.
2. Fit the calibration line through the remaining runs.
3. Ask that line what heater power the hidden run's dLL/dt corresponds to, and
   note how far off it is from the hidden run's actual heater readback.
4. Put the run back, hide the next one, and repeat for every run.

That is *leave-one-out*. It is fairer than checking the line against the
points it was fit to, because a line always looks good on its own points. The
misses for one calibration are summarised as an *RMS*, or root-mean-square:
square each miss, average the squares, take the square root. The result is a
typical miss in watts, with big misses counting extra.

There were 160 calibrations with 4 or more runs. Each gets one RMS per fit,
and the table shows the *median* over the 160: the middle calibration once
sorted. The *mean* (average) is shown too. It is much larger, because a few
calibrations with very bad runs drag it up.

| Run fit | Median leave-one-out RMS (W) | Mean (W) |
|---|---|---|
| `linregress` | 2.34 | 7.6 |
| `theilslopes` | 2.35 | 9.4 |
| `siegelslopes` (official) | 2.66 | 12.8 |

`siegelslopes` did better in only 60 of the 160 calibrations. A *Wilcoxon
signed-rank test* puts a number on how surprising that is. It pairs up each
calibration's two scores and looks at which is smaller and by how much. Its
*p-value*, 0.001, answers: if the two fits were really equally good, how often
would a split this lopsided happen by luck? About 1 time in 1000. So the
difference is real. A p-value says nothing about size, though, and the size
here is about 0.3 W.

By year (median RMS, `linregress` vs `siegelslopes`): 2022 3.13 vs 3.37 W,
2023 1.47 vs 1.72 W, and 2025 a tie at 1.53 vs 1.51 W.

**Q0 heater run.** The heater run inside each Q0 measurement has a known heat,
so it is a second test. Read through its calibration, it came out within a
median 4.4 W (`linregress`) vs 3.8 W (`siegelslopes`). `siegelslopes` was
closer in 144 of 279 measurements, close to an even split, and p = 0.59. A
split like that happens by luck more often than not, so this test cannot tell
the fits apart.

**What drives the gap.** For each run, the gap between the two fits' slopes was
compared with two things: how curved the LL trace is (the size of the bend in a
gently curved fit, against the straight part), and the share of readings that
are outliers (far from the line). *Spearman correlation* scores how
consistently one goes up when the other does. It runs from −1 to 1: 0 means no
relation, 1 means they always rise together. The gap tracks curvature strongly (0.81) and outliers only
weakly (0.30). So the fits disagree mainly because the traces bend slightly,
not because of wild readings. Robust fits are built for wild readings, which
fits with `linregress` doing at least as well here.

Trimming the first 10–50% of each run did not improve either fit.

**LL linearity in band.** Each run was split into six pieces, and each piece's
slope divided by the whole-run slope. A ratio of 1.0 means that piece falls at
the run's average rate. From 90.0 to 92.5 every 0.5-wide bin is within ±2% of
1.0. From 92.5 to 93.0, where runs start right after the fill, pieces are 8.5%
steeper. Level and time are tied together, since LL only falls during a run.
So this cannot tell a sensor effect from settling after the fill.

!!! warning "Open questions for the area physicist"

    The code collects data with DS LL above `MIN_DS_LL`, because the sensor is
    not linear over its full range
    <span class="cite">`q0_utils.py “isn't linear over the full range”`</span>.

    CHECK: is the DS LL sensor linear across 90–93? The data above fits a
    linear sensor up to 92.5, but no reference has been found.

    CHECK: is the steeper 92.5–93 stretch the sensor, or settling after the
    fill?

    CHECK: the comparison treats heater readback as exact. Its accuracy is
    unknown. A constant offset or scale error would not favour either fit.
    Random run-to-run error would add the same scatter to both.

**Reading.** The data mildly favours `linregress`, by about 0.3 W on
calibration scatter. That is not enough on its own to change the official fit.
Changing it would change every Q0 recomputed on load.

For scale, the paper puts the method's overall error at 15–20%. Most of that
comes from line-fit errors carried into later fits, and the method is very
sensitive to heat-load changes during a run, such as helium pressure
oscillations <span class="cite">Zacarias et al., SRF2023, [MOPMB090](https://proceedings.jacow.org/srf2023/papers/mopmb090.pdf)</span>.

## 8. What is stored, and what is read back

The data files store a "dLL/dt" value for every run. Nothing reads it. On load,
every slope is refit from "Liquid Level Data". Records saved before
`siegelslopes` became the default (Nov 2022) hold `linregress` values.

The index's "Calculated Q0" is whatever the fit in use at the time gave, so a
2022 Q0 in the index can differ from the one the app shows on load. Across the
167 pre-switch measurements the median difference is 2.8%. #415 stops
`load_data` from rewriting the stored value with a refit.
