How RF commissioning is built

An onboarding map of applications/rf_commissioning/: the layers, what one button click passes through on its way to the machine and to SQLite, how a phase is written, what each implemented phase writes to EPICS, and the places where the code surprises people. Everything here is read from upstream main. Hardware questions the code does not answer are marked CHECK:.

1. The shape of the app

Commissioning is nine phases run in a fixed order per cavity. Each phase has a stored value, a record attribute and a data model, all declared in one registry models/registry.py::create_phase_registry. Today three phases are real. The rest have a tab with a placeholder display whose Run button only logs ui/displays/base_placeholder.py::BasePlaceholderDisplay.on_run_automated_test “This is a placeholder implementation”.

Five layers, top to bottom:

LayerWhereJob
Containerui/multi_phase_screen.py, ui/container/ The window. Header, cavity picker, progress bar, notes, one tab per phase. Built from mixins.
Displayui/displays/ One tab's widgets. Forwards button clicks to its controller.
Controllerui/controllers/ Runs the phase on a background thread, pushes results back to the GUI with Qt signals, calls the session to open and close attempts.
Phasephases/ The steps. This is the only layer that commands hardware, through Cavity, SSA, Piezo and StepperTuner from utils/sc_linac/.
Session and storagesession_manager.py, services/workflow_service.py, models/persistence/ CommissioningSession is the facade the UI calls. WorkflowService owns phase attempts. Repositories own SQL.
The repo-wide CLAUDE.md describes a backend/ frontend/ launcher/ layout and Worker(QThread) threading. This app uses neither. There is no launcher/ directory: the entry point is cli/launchers.py::launch_rf_commissioning. Threads are plain threading.Thread ui/controllers/piezo_pre_rf_controller.py::PiezoPreRFController._run_phase_in_background “Thread(target=worker, daemon=True).start()”.

An operator presses Run automated test on the Piezo Pre-RF tab. Step through what happens. The other two implemented phases follow the same path with their own controller.

3. Writing a phase

A phase subclasses PhaseBase and implements five members: phase_type, validate_prerequisites, get_phase_steps, execute_step and finalize_phase phases/phase_base.py::PhaseBase “Subclasses must implement:”.

  • get_phase_steps returns an ordered list of step names. SSACharPhase is the cleanest short example phases/ssa_char.py::SSACharPhase.get_phase_steps.
  • execute_step dispatches on the name and returns a PhaseStepResult carrying SUCCESS, RETRY, FAILED or SKIP phases/phase_base.py::PhaseResult.
  • RETRY waits retry_delay_seconds, default 5 s phases/phase_base.py::PhaseStepResult “retry_delay_seconds: float = 5.0”, up to three times per step phases/phase_base.py::PhaseBase.__init__ “self._max_retries_per_step: int = 3”.
  • Abort is a flag, not an interrupt phases/phase_base.py::PhaseContext.request_abort “self.abort_requested = True”. A long step has to check it itself.
PhaseBase.run() exists but no controller calls it. Each of the three controllers has its own step loop and calls private phase methods directly, for example ui/controllers/ssa_char_controller.py::SSACharController._run_phase_in_background “self.phase._mark_phase_started()”. So there are four step loops, and they do not all do the same bookkeeping. Read the controller for the phase you are touching, not just PhaseBase.

Two things that are not where you would look

  • Phase status is not stored on the record. On load it is rebuilt from the latest attempt of each phase models/persistence/database_helpers.py::build_workflow_state “if previous is None or attempt >= previous[0]:”. The in-memory record.phase_status that PhaseBase updates is not what persists.
  • phase_history is not persisted. It is reset on every load repositories/records.py::RecordRepository.row_to_record “phase_history=[],”.

Two people, one cavity

Saves use optimistic locking. The update only matches if the version is unchanged since load repositories/records.py::RecordRepository.save_record “WHERE id = ? AND version = ?”. The window also polls every 5 s and reloads if someone else saved ui/container/sync.py::_SyncMixin._check_for_external_changes “if local_version is not None and db_version > local_version:”. Measurement notes skip the version check repositories/measurements.py::MeasurementRepository.append_measurement_note “"UPDATE measurement_history SET notes = ? WHERE id = ?",”.

6. Where newcomers trip

  1. Three prerequisite checks that disagree. CommissioningRecord.can_start_phase and WorkflowService._validate_phase_prerequisites accept a previous phase that is complete or skipped. CommissioningSession.can_run_phase accepts complete only rf_commissioning/session_manager.py::CommissioningSession.can_run_phase “if previous_status != PhaseStatus.COMPLETE:”.
  2. Frequency tuning's stage checks are not in its step list. They exist only in execute_step's dispatch, and only Stage 1 opens an attempt ui/controllers/frequency_tuning_controller.py::FrequencyTuningController._find_open_phase_instance_id “Only Stage 1 opens a phase instance”.
  3. The batch Piezo window skips the session facade. It calls the workflow service directly and writes no measurement history ui/controllers/batch_piezo_pre_rf_controller.py::BatchPiezoPreRFController._init_record_and_context “phase_start = self.session.workflow.start_phase_for_record(”.
  4. Docs drift. docs/applications/rf_commissioning.md says only the Piezo tab shows by default. All phases with a record attribute show ui/container/phase_specs.py::DEFAULT_BETA_VISIBLE_PHASES.
  5. Small naming bumps. self._controller in FrequencyTuningDisplay vs self.controller elsewhere. ssa_char in the registry but "ssa_characterization" in CommissioningRecord.to_dict.

7. Running and testing it

Launch the app

Install once with pip install -e ".[dev,test]" from the repo root. Then pick how much of the machine you want:

You wantRunWhat you get
Layout only PYDM_DEFAULT_PROTOCOL=fake sc-rf-comm The window opens with no EPICS. PV values are zero or empty. Good for UI work.
Live fake data sc-sim in one terminal, then sc-rf-comm in another A caproto IOC serving simulated cavity PVs. Phases can run end to end against it. See Getting started.
The real machine sc-rf-comm on a control-room host Phases write to the PVs in section 5.

sc-linac rf-commissioning launches the same window through the unified CLI cli/launchers.py::launch_rf_commissioning “MultiPhaseCommissioningDisplay, *sys.argv[1:], standalone=standalone”.

Which database it opens

There is no command-line flag for the database path. The window always builds a default CommissioningSession() ui/multi_phase_screen.py::MultiPhaseCommissioningDisplay.__init__ “self.session = session or CommissioningSession()”, which picks the path by OS rf_commissioning/session_manager.py::get_default_db_path “db_dir = get_srf_base_dir() if is_linux() else get_database_dir()”:

  • Linux: /home/physics/srf/commissioning.db utils/platform_paths.py::get_srf_base_dir “return Path("/home/physics/srf")”
  • macOS: ~/.sc_linac_physics/databases/commissioning.db. The docstring on get_default_db_path still says ~/databases/, which is out of date.
On Linux that is the same path on every host that mounts /home/physics. Saving there from a dev session saves into the commissioning records. 
# CHECK: which hosts share /home/physics/srf, and is it the production DB?
For safe local work, run on a Mac, or construct the window yourself with MultiPhaseCommissioningDisplay(session=CommissioningSession(db_path=...)).

  • Tests: pytest tests/applications/rf_commissioning -n auto. About 900 tests, about 12 s.
  • EPICS is faked for the whole test run by tests/conftest.py, which installs a fake PV class at configure time.
  • Three patterns worth copying:
    • Real SQLite in tmp_path: tests/applications/rf_commissioning/test_session_workflow.py
    • Controller against a stub view: tests/applications/rf_commissioning/test_piezo_pre_rf_controller.py
    • Container methods on a SimpleNamespace stub: tests/applications/rf_commissioning/ui/test_multi_phase_screen.py
